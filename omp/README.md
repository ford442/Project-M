# Prebuilt Emscripten libomp

`omp.zip` holds the two files the Emscripten OpenMP build needs:

| File | Purpose |
|------|---------|
| `libomp.a` | LLVM OpenMP runtime, static, wasm32 |
| `omp.h`    | The header libprojectM and the WASM host compile against |

It is the repo's one deliberately-committed prebuilt binary. The `.a` is zipped
only to get past the `*.a` rule in `.gitignore`; `scripts/build_wasm_install.sh`
and `scripts/build_projectm.sh` unpack it into this directory automatically.

## Provenance of the current archive

| | |
|---|---|
| Built | 2026-09-12 |
| Source | `llvm/llvm-project` tag `llvmorg-19.1.0`, `openmp/` subtree |
| Toolchain | Emscripten 6.0.3 (clang 23) |
| Built by | `scripts/build_libomp_emscripten.sh` |
| `libomp.a` | 806,884 bytes |
| Target features | `atomics, bulk-memory, bulk-memory-opt, call-indirect-overlong, multivalue, mutable-globals, nontrapping-fptoint, reference-types, sign-ext` |

`omp.h` is **not** the one generated by that build. It is the newer header the
repo already carried, kept as-is because it is what libprojectM currently
compiles against. The only differences are added allocator-trait enumerators
that projectM does not use.

## Rebuilding

```sh
source /path/to/emsdk/emsdk_env.sh
scripts/build_libomp_emscripten.sh          # writes ./libomp.a at the repo root
```

Then repackage and update the provenance table above:

```sh
cp omp/omp.h libomp.a /tmp/omp-stage/ && (cd /tmp/omp-stage && zip -9 -X omp.zip omp.h libomp.a)
```

### Two things that will bite you

**Wasm feature flags.** `build_libomp_emscripten.sh` passes `LIBOMP_WASM_FLAGS`
(`-pthread -matomics -mbulk-memory …`) into the libomp CMake configure. Without
them the final wrapper link fails with:

```
wasm-ld: error: --shared-memory is disallowed by kmp_alloc.cpp.o because it was
not compiled with 'atomics' or 'bulk-memory' features.
```

**Toolchain skew.** A `libomp.a` built by a much newer clang declares wasm
features (`bulk-memory-opt`, `call-indirect-overlong`) that an older Binaryen
does not recognise, and `wasm-opt` aborts with `Unknown option
'--enable-bulk-memory-opt'`. Build it with the same SDK you link with. CI
(`.github/workflows/build_emscripten.yml`) pins emsdk 3.1.53 and rebuilds libomp
from source rather than using this archive, so the two can drift.
